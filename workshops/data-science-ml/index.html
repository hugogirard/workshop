    Module 2 Engineer features

    Models learn from features, not raw rows. We assemble a clean feature matrix — price, promo, web sessions, last week's units — and the label to predict.

    Docs: Data prep & modeling

    Learn more DS process Prep with Wrangler
    ▸ Build the feature matrix ~10 min

    What & why: Select the predictive columns and split into features X and label y. prev_week_units is a lag feature — last week's demand is a strong predictor of this week's.

    features = ["avg_price_cad", "promo_flag", "web_sessions", "prev_week_units"]
X = df[features]
y = df["units_sold"]
from sklearn.model_selection import train_test_split
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42)
    For data prosThe lag feature encodes autocorrelation cheaply without a full time-series model — a pragmatic baseline before you reach for ARIMA/Prophet.
    Expected resultX_train.shape shows 4 feature columns and ~18 training rows.

    Module 3 Train & track with MLflow

    Fabric has a built-in MLflow experience: every training run logs its params, metrics and model artifact, so you can compare runs and reproduce the winner. This is version control for models.

    Docs: ML experiments (MLflow)

    Learn more Experiments Models MLflow docs
    ▸ Train a regressor & log the run ~14 min

    What & why: Train a RandomForest, evaluate on the test set, and log everything to a named MLflow experiment so the run is comparable and reproducible.

    import mlflow
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error

mlflow.set_experiment("contoso-demand-forecast")
with mlflow.start_run(run_name="rf-baseline"):
    n_estimators = 200
    model = RandomForestRegressor(n_estimators=n_estimators, random_state=42)
    model.fit(X_train, y_train)
    mae = mean_absolute_error(y_test, model.predict(X_test))

    mlflow.log_param("n_estimators", n_estimators)
    mlflow.log_metric("mae", mae)
    mlflow.sklearn.log_model(model, "model")
    print("MAE:", round(mae, 2))
    For data prosThe experiment is the audit trail: params + metrics + the serialized model, side by side across runs. Change n_estimators, re-run, and compare in the experiment UI.
    NoteWith this tiny dataset the goal is the workflow, not accuracy — MAE will be rough. Real forecasts use far more history and features.
    Expected resultA run appears under the contoso-demand-forecast experiment with a logged mae and a model artifact.

    Module 4 Register & batch-score with PREDICT

    Register the best run as a named model, then use Fabric's scalable PREDICT to batch-score next week's features — inference at Spark scale, no serving infra to stand up.

    Docs: Model registry Score with PREDICT

    Learn more Register a model PREDICT
    ▸ Register the model & score next week ~14 min

    What & why: Registering gives the model a name + versions so downstream jobs reference a stable artifact. Then score the unlabeled next-week features.

    import mlflow
# Register the run's model (grab the run_id from the experiment UI or last run)
result = mlflow.register_model(f"runs:/{run.info.run_id}/model", "contoso_demand_rf")

# Batch score next week's features
score = spark.read.option("header", True).csv("Files/ml/score-next-week.csv")
from synapse.ml.predict import MLFlowTransformer
predictions = MLFlowTransformer(
    inputCols=["avg_price_cad","promo_flag","web_sessions","prev_week_units"],
    outputCol="forecast_units",
    modelName="contoso_demand_rf",
    modelVersion=1
).transform(score.toPandas())
predictions
    For data prosRegistry = a governed catalog of model versions (stage/aliases). PREDICT applies an MLflow model across a Spark dataframe — batch inference without exporting the model to a separate scoring service.
    Expected resultThree forecast_units values (one per SKU) for the week of 2026-03-02.

    Module 5 Write predictions to gold & serve

    Predictions are only useful if the business sees them. Write gold.demand_forecast and serve it in Power BI Direct Lake — the report now shows a forward-looking number next to actuals.

    Docs: Direct Lake Enrich & operationalize

    Learn more Direct Lake Serve predictions
    ▸ Persist gold.demand_forecast ~10 min

    What & why: Save the predictions as a gold Delta table so BI can read them with Direct Lake, alongside the medallion actuals.

    from pyspark.sql import functions as F
pred_sdf = spark.createDataFrame(predictions)[
    ["sku", "week_start", "forecast_units"]]
(pred_sdf.write.mode("overwrite").saveAsTable("gold.demand_forecast"))
    For data prosBecause gold is Delta, Power BI reads the forecast with Direct Lake — no import refresh — so the report updates whenever the scoring job reruns.
    Expected resultgold.demand_forecast holds one forecast per SKU; a report shows forecast vs recent actuals.
