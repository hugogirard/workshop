    Module 2 Clean-and-load with Dataflow Gen2

    Dataflow Gen2 is low-code ELT built on Power Query — 300+ transforms, a visual preview, and a lakehouse data destination. Perfect for the messy supplier price list: trim, fix types, standardize currency, then land it in bronze.

    Docs: Dataflow Gen2 overview

    Learn more Dataflow Gen2 Data destinations Power Query
    ▸ Build the price-list Dataflow ~15 min

    What & why: Clean the data as it loads so bronze is usable. Create + New → Dataflow Gen2, Get data → Text/CSV, upload supplier-prices.csv, then apply: trim text columns, set unit_cost to decimal and effective_date to date. 

    1. Use first row as headers
2. Trim + Clean on product_name, sku, currency
3. Change type: unit_cost -> Decimal, effective_date -> Date
4. Keep latest effective_date per (supplier_id, sku)
    let
    Source = Csv.Document(File.Contents("supplier-prices.csv"),
        [Delimiter=",", Columns=6, Encoding=65001]),
    Prom   = Table.PromoteHeaders(Source),
    Trim   = Table.TransformColumns(Prom,
        {{"product_name", Text.Trim}, {"sku", Text.Trim}, {"currency", Text.Trim}}),
    Typed  = Table.TransformColumnTypes(Trim,
        {{"unit_cost", type number}, {"effective_date", type date}})
in
    Typed
    For data prosPower Query's M is a functional, step-by-step transform script — each applied step is a named, reorderable line, so the whole cleanse is auditable (unlike a black-box script).
    NoteSet the Data destination to lh_contosomart → table bronze.supplier_prices, update method Replace.
    Expected resultPublishing + refreshing the Dataflow creates bronze.supplier_prices with trimmed names and typed columns.

    Module 4 Parameterize & go incremental

    Reprocessing every file every day is wasteful and error-prone. Parameterize the source by date so each run only ingests the new partition — the essence of incremental loading.

    Docs: Pipeline runs Copy activity

    Learn more Pipeline parameters Expression language Incremental copy
    ▸ Add a runDate parameter ~12 min

    What & why: A parameter makes one pipeline reusable for any day. Add a pipeline parameter runDate and build the file name dynamically in the Copy source path.

    Parameter:  runDate  (string, default 2026-03-02)
Source file (dynamic):
    @concat('daily-sales-', pipeline().parameters.runDate, '.csv')

    Run once with runDate = 2026-03-02 to append day 2 only.

    For data prosThis is the watermark/partition pattern: the pipeline is idempotent per date, so a re-run of day 1 never double-loads day 2. For DB sources, Copy job does true CDC/incremental automatically.
    NoteUse append, not replace, so partitions accumulate. Real pipelines often store the last watermark in a control table.
    Expected resultbronze.daily_sales now holds 7 rows (day 1 + day 2) after the parameterized run.

    Module 5 Orchestrate the end-to-end flow

    Ingestion rarely runs alone. Chain the Dataflow, the Copy, and the silver Notebook into one pipeline with success dependencies and a schedule — so bronze loads then silver cleanses, automatically, every morning.

    Docs: Pipeline runs & scheduling Notebooks

    Learn more Activities & control flow Schedules & triggers Notebook activity
    ▸ Chain Dataflow → Copy → Notebook ~15 min

    What & why: Dependencies enforce order and safety — silver only runs if bronze succeeded. On the pipeline canvas add the three activities and connect them On success:

    [Dataflow: clean supplier_prices]
        └─(on success)─> [Copy: daily_sales]
                                └─(on success)─> [Notebook: bronze -> silver cleanse]
    For data prosThis is a DAG — the same control-flow model as SSIS precedence constraints or Airflow tasks, drawn on a low-code canvas.
    NoteReuse the silver PySpark notebook from the medallion lab as the third activity. Then Schedule the pipeline (e.g. daily 06:00).
    Expected resultA single run turns green end-to-end: bronze refreshed, then silver rebuilt.

    Module 6 Monitor, retry & govern

    A pipeline you can't see is a pipeline you can't trust. Use run history, retries and failure alerts to make the ingest reliable and observable — the operational half of data integration.

    Docs: Monitor pipeline runs

    Learn more Run history Monitoring hub Event triggers
    ▸ Add retries & a failure alert ~10 min

    What & why: Transient failures happen; automatic retries and an alert keep small blips from becoming missed loads. On the Copy activity set Retry = 2, Retry interval = 30s. Add an Office 365 Outlook / Teams activity on the failure path, or an Activator alert on the pipeline.

    For data prosCheck the Monitoring hub for per-activity duration, rows read/written, and input/output — your equivalent of pipeline run logs + row counts for reconciliation.
    NoteGovernance carries over: pipeline items live in the workspace and honor workspace roles and OneLake security on the lakehouse tables they write.
