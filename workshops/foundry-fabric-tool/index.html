    Module 0 How the Fabric tool grounds an agent

    The Fabric tool turns your enterprise data into a conversational answer inside the Foundry agent — and does it under the end user's own identity.

    Docs: Fabric tool Agent identity

    ▸The end-to-end flow~5 min

    Intent: understand what happens when a user asks a data question.

    • You publish a Fabric data agent (done in Act 8) and connect it to Foundry.
    • A user asks the concierge a question; the agent decides whether to use the Fabric tool.
    • If so, it uses the end user's identity to generate queries over data they can access.
    • The agent turns the returned results into its answer.
    Why OBO mattersIdentity passthrough (On-Behalf-Of) means the same Purview policies, RLS and CLS from Act 8 keep applying — the agent can't leak data the user couldn't see.
    PreviewThe Fabric tool is in public preview — fine for enablement, not recommended for production workloads yet.

    Module 1 Prerequisites & permissions

    Both sides must line up: the data agent published in Fabric, the Foundry project, and the right access for every user who will ask questions.

    Docs: Prerequisites Source permissions

    ▸Check both sides & grant access~8 min

    Intent: avoid the most common failure — an unauthorized tool call.

    • The Act 8 data agent is published (paid F2+/P1+ capacity).
    • Assign developers and end users at least the Foundry User RBAC role.
    • Give each end user at least READ on the Fabric data agent, plus the minimum permission on each source (Read on lakehouse; SELECT on warehouse tables; Reader on the KQL DB; Read on the semantic model — RLS/CLS still apply).
    • Data agent + Foundry project in the same tenant; data agent + sources in the same region.
    • Use user identity auth — service principal isn't supported for the Fabric tool.
    Expected resultYou can open the Fabric data agent and query it directly in Fabric as your test user.

    Module 2 Create the Microsoft Fabric connection

    Foundry reaches the data agent through a project connection built from two GUIDs in the data agent's URL.

    Docs: Set up the Fabric connection

    ▸Copy the two GUIDs~4 min

    Intent: get workspace_id and artifact_id from Fabric.

    Open your data agent in Fabric and read them from the URL path:

    .../groups/<workspace_id>/aiskills/<artifact_id>...
# Both values are GUIDs. These are the same IDs you noted at the end of Act 8.
    ▸Create the connection in Foundry~6 min

    Intent: register the data agent as a connected resource.

    • In the Foundry portal open your contosomart project → Manage → Project details → Connected resources.
    • Create a connection of type Microsoft Fabric; enter the workspace_id and artifact_id; save.
    • Copy the connection ID — it looks like:
    /subscriptions/<subscriptionId>/resourceGroups/<rg>/providers/Microsoft.CognitiveServices/accounts/<foundryAccount>/projects/contosomart/connections/<connectionName>
    Expected resultA Microsoft Fabric connection (e.g. contosomart-fabric) exists, and you have its connection ID.

    Module 3 Attach the Fabric tool to the agent

    Add the Fabric tool to contosomart-concierge in the portal, or define it in code. Forcing tool use guarantees the agent grounds its answer.

    Docs: Create an agent with the Fabric tool

    ▸Portal: add the tool~5 min

    Intent: the no-code path.

    Open the agent, add the Microsoft Fabric tool, and pick your contosomart-fabric connection. Add tool guidance to the instructions so the model calls it: 

    For customer, product, sales, inventory or clickstream data, use the Fabric tool.
    ▸Code: create the agent with the tool~12 min

    Intent: the code-first path, in your language of choice. Set the project endpoint and Fabric connection name/ID first; sign in with az login.

    from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import (
    PromptAgentDefinition, MicrosoftFabricPreviewTool,
    FabricDataAgentToolParameters, ToolProjectConnection,
)

PROJECT_ENDPOINT = "https://<resource>.ai.azure.com/api/projects/contosomart"
FABRIC_CONNECTION_NAME = "contosomart-fabric"

project = AIProjectClient(endpoint=PROJECT_ENDPOINT, credential=DefaultAzureCredential())
openai = project.get_openai_client()
fabric = project.connections.get(FABRIC_CONNECTION_NAME)

agent = project.agents.create_version(
    agent_name="contosomart-concierge",
    definition=PromptAgentDefinition(
        model="gpt-4.1-mini",
        instructions="You are the ContosoMart concierge. For sales, inventory or "
                     "customer data, use the Fabric tool. Never invent numbers.",
        tools=[MicrosoftFabricPreviewTool(
            fabric_dataagent_preview=FabricDataAgentToolParameters(
                project_connections=[ToolProjectConnection(project_connection_id=fabric.id)]
            )
        )],
    ),
)

response = openai.responses.create(
    tool_choice="required",
    input="What were total sales last week?",
    extra_body={"agent_reference": {"name": agent.name, "type": "agent_reference"}},
)
print(response.output_text)
    var projectEndpoint = "https://<resource>.ai.azure.com/api/projects/contosomart";
var fabricConnectionName = "contosomart-fabric";

AIProjectClient projectClient = new(new Uri(projectEndpoint), new DefaultAzureCredential());
AIProjectConnection fabric = projectClient.Connections.GetConnection(fabricConnectionName);

FabricDataAgentToolOptions fabricTool = new()
{
    ProjectConnections = { new ToolProjectConnection(projectConnectionId: fabric.Id) }
};
DeclarativeAgentDefinition def = new(model: "gpt-4.1-mini")
{
    Instructions = "You are the ContosoMart concierge. Use the Fabric tool for data.",
    Tools = { new MicrosoftFabricPreviewTool(fabricTool) }
};
AgentVersion agent = projectClient.AgentAdministrationClient
    .CreateAgentVersion(agentName: "contosomart-concierge", options: new(def));

var responseClient = projectClient.ProjectOpenAIClient
    .GetProjectResponsesClientForAgent(agent.Name);
CreateResponseOptions opts = new()
{
    ToolChoice = ResponseToolChoice.CreateRequiredChoice(),
    InputItems = { ResponseItem.CreateUserMessageItem("What were total sales last week?") },
};
Console.WriteLine(responseClient.CreateResponse(opts).GetOutputText());
    import { DefaultAzureCredential } from "@azure/identity";
import { AIProjectClient } from "@azure/ai-projects";

const PROJECT_ENDPOINT = "https://<resource>.ai.azure.com/api/projects/contosomart";
const FABRIC_CONNECTION_NAME = "contosomart-fabric";

const project = new AIProjectClient(PROJECT_ENDPOINT, new DefaultAzureCredential());
const openai = project.getOpenAIClient();
const fabric = await project.connections.get(FABRIC_CONNECTION_NAME);

const agent = await project.agents.createVersion("contosomart-concierge", {
  kind: "prompt",
  model: "gpt-4.1-mini",
  instructions: "You are the ContosoMart concierge. Use the Fabric tool for data.",
  tools: [{
    type: "fabric_dataagent_preview",
    fabric_dataagent_preview: {
      project_connections: [{ project_connection_id: fabric.id }],
    },
  }],
});

const response = await openai.responses.create(
  { input: "What were total sales last week?" },
  { body: { agent_reference: { name: agent.name, type: "agent_reference" }, tool_choice: "required" } },
);
console.log(response.output_text);
    # AGENT_TOKEN is a credential — keep it secret, never commit it.
export AGENT_TOKEN=$(az account get-access-token --scope "https://ai.azure.com/.default" --query accessToken -o tsv)

curl --request POST \
  --url "$FOUNDRY_PROJECT_ENDPOINT/openai/v1/responses" \
  -H "Authorization: Bearer $AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "model": "'$FOUNDRY_MODEL_DEPLOYMENT_NAME'",
    "input": "What were total sales last week?",
    "tool_choice": "required",
    "tools": [{
      "type": "fabric_dataagent_preview",
      "fabric_dataagent_preview": {
        "project_connections": [{ "project_connection_id": "'$FABRIC_PROJECT_CONNECTION_ID'" }]
      }
    }]
  }'

    Module 5 Troubleshoot & alternatives

    A quick reference for the errors you'll most likely hit, plus when to reach for the Fabric IQ tool instead.

    Docs: Troubleshooting Fabric IQ tool

    ▸Common errors~6 min
    Symptom Likely cause Fix
    unauthorized User lacks access to the data agent or its sources Grant READ in Fabric; use user identity auth
    Artifact Id ... valid GUID Bad workspace/artifact ID Recopy both GUIDs from the data-agent URL and recreate the connection
    Agent won't use the tool Tool not configured or prompt doesn't trigger it Confirm the tool is attached; add tool guidance or set tool_choice="required"
    configuration not found Data agent not published Publish it in Fabric and confirm its sources are valid
    Empty results Query doesn't match available data Test the question directly in the Fabric data agent first
    ▸When to use Fabric IQ instead~4 min

    Intent: know the sibling tool.

    The Fabric IQ tool (part of the Microsoft IQ family) lets an agent reason over Fabric data — data agents, ontologies and Power BI semantic models. Use the Fabric data agent tool when you've already curated a conversational data agent (this lab); consider Fabric IQ when you want the agent to reason directly over semantic models or an ontology.
