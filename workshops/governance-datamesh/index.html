    Module 0 Why govern — the data mesh idea

    As data grows, central IT can't own every dataset. A data mesh decentralizes ownership by business domain, with federated governance — each team owns its data as a product, under shared rules. Fabric implements this natively.

    Docs: Domains Fabric overview

    Learn more Domains & data mesh OneLake Catalog Governance overview
    ▸ Centralized vs federated governance ~6 min

    What & why: Traditional data platforms govern centrally, which becomes a bottleneck. A data mesh delegates domain-level control (rules, certification, default labels) to the business units, while the tenant keeps guardrails — the best of both.

    For data prosThink enterprise data catalog + RBAC delegation + data contracts: domains are the org chart for your data, and "data as a product" means each dataset has an owner, docs, quality, and an SLA.
    Expected resultYou can explain why ContosoMart's estate should be split into domains rather than governed as one pile.

    Module 2 · Illustrated Create domains & assign workspaces

    In the admin portal, a Fabric admin creates domains and delegates them to domain admins/contributors, then assigns workspaces. Assigning a workspace tags all its items with the domain — the mechanical heart of the mesh.

    Docs: Create & manage domains

    Learn more Domains admin Workspace roles
    ▸ Create a domain & assign the workspace ~12 min

    What & why: Create the domains from your plan and assign ContosoMart-Analytics so its items get a domain attribute (in a real org you'd split into a workspace per domain). 

    Admin portal -> Domains -> Create new domain: "Sales"
  - Add domain admins (business owner)
  - Assign workspaces: by name / by admin / by capacity
Repeat for Marketing, Finance, Operations
Optionally: create subdomains (Storefront, Web, Reporting, Supply)
    For data prosRoles mirror RBAC: Fabric admin creates domains, domain admin owns one domain's settings, domain contributor (a workspace admin) assigns their workspace. Some tenant settings can be delegated to domain level — federated governance in action.
    Note (why illustrated)Creating domains needs Fabric admin rights a trial user often lacks — read along, or do it if you're a tenant admin.
    Expected resultThe workspace shows a domain badge; items are filterable by domain in the catalog.

    Module 4 Endorse: promote & certify

    Endorsement is a trust signal: Promoted means "the team vouches for this," Certified means "an authorized reviewer approved it to a standard." It's how consumers tell gold from a random draft.

    Docs: Endorsement

    Learn more Endorsement overview Promote / certify
    ▸ Promote and certify products ~10 min

    What & why: Promote the products you own (self-service), and — if you're a certifier — certify the finance and sales gold per the blueprint.

    Item settings -> Endorsement
  Promoted : gold.demand_forecast, Clickstream        (team vouches)
  Certified: gold.daily_sales, gold.customer_ltv,
             wh_contoso_finance.vw_sales               (authorized reviewer)
    For data prosCertification ≈ a signed, approved release: only designated certifiers (set at tenant or domain level) can grant it, so the badge actually means something.
    NoteAnyone with write access can Promote; Certify is restricted to configured certifiers — a domain-delegated setting.
    Expected resultThe gold products show Promoted/Certified badges and rank higher in catalog search.

    Module 5 · Illustrated Protect with sensitivity labels & DLP

    Sensitivity labels (from Microsoft Purview) classify data and enforce protection that travels with it — even on export. DLP policies watch for risky sharing. This is how the finance numbers stay confidential end-to-end.

    Docs: Information protection

    Learn more Sensitivity labels Apply labels DLP
    ▸ Label finance as Confidential ~10 min

    What & why: Apply a Confidential label to the finance warehouse view and semantic model; the label (and its encryption/usage rules) follows the data into exports and downstream reports.

    For data prosUnlike table RLS (which controls rows in place), a sensitivity label is classification + protection that travels — it stays attached when the data leaves Fabric (e.g. an Excel export), enforced by Purview.
    Note (why illustrated)Labels are published from Microsoft Purview and enabled by an admin, and can be set as a domain default. Read along unless your tenant already has labels configured.
    Expected resultThe finance items show a Confidential label; exports carry it.
