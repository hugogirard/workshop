    Module 0 The silo problem & zero-copy

    Most orgs have mission-critical data trapped in silos, reachable only via brittle ETL. Fabric's answer is to bring data into OneLake without copying it — shortcuts (reference in place) and mirroring (managed replica). Understand the choice before you build.

    Docs: OneLake overview Mirroring overview

    Learn more Shortcuts Mirroring OneLake
    ▸ Shortcut vs mirror vs copy ~6 min

    What & why: A shortcut references data where it lives (ADLS, S3, Dataverse, another workspace) — nothing is copied, updates are live. Mirroring creates a managed, near-real-time Delta replica of an operational database. A pipeline copy physically moves data. Use the lightest tool that meets the freshness/ownership need.

    For data prosShortcut ≈ a database view or filesystem symlink across storage accounts; mirroring ≈ a managed read replica purpose-built for analytics — but landing as open Delta in OneLake, not a proprietary store.
    Expected resultYou can pick shortcut vs mirror vs copy for a given source and justify it.
    ▸ Reuse the ContosoMart workspace ~3 min

    What & why: Keep everything in ContosoMart-Analytics so shortcut/mirror data can join the medallion gold.

    NoteTrial is F4/F64, no Copilot. Mirroring an external DB needs a live Azure source — Module 3 is illustrated if you don't have one.
    Expected resultYou're in ContosoMart-Analytics with the medallion lakehouse present.

    Module 1 Create a shortcut to external storage

    A shortcut makes external data appear inside your lakehouse with zero copy and live updates. We reference a partner roastery feed as if it lived in ADLS/S3.

    Docs: OneLake shortcuts

    Learn more Shortcuts concept ADLS shortcut Amazon S3 shortcut
    ▸ Upload the feed & make a shortcut ~12 min

    What & why: To keep this hands-on without an S3 bucket, upload partner-roastery-feed.csv to lh_contosomart/Files/external/, then create an internal OneLake shortcut to that folder under Files/shortcuts/partner_feed.

    In the lakehouse: Files → New shortcut → Microsoft OneLake, pick the external folder, name it partner_feed.

    For data prosThe shortcut is a pointer, not a copy — change the source file and the shortcut reflects it instantly. In production the target is ADLS Gen2, Amazon S3, Google Cloud Storage, Dataverse, or another Fabric workspace.
    NoteExternal targets (ADLS/S3) need a connection + credentials; the OneLake-to-OneLake shortcut here needs none, so everyone can complete it.
    Expected resultFiles/shortcuts/partner_feed shows the CSV without a second physical copy.

    Module 2 Use the shortcut (reference vs copy)

    A shortcut can be queried in place or materialized into a bronze Delta table. Knowing when to reference and when to copy is the real lesson.

    Docs: Shortcuts Delta tables

    Learn more Shortcuts Delta in Fabric
    ▸ Read the shortcut in a notebook ~10 min

    What & why: Read straight from the shortcut path — no copy — then optionally persist to bronze if you need Delta features (time travel, V-Order) on it.

    df = spark.read.option("header", True).csv(
    "Files/shortcuts/partner_feed/partner-roastery-feed.csv")
df.show()

# Materialize to bronze only if you need Delta features on it:
df.write.mode("overwrite").saveAsTable("bronze.partner_feed")
    For data prosReference (query in place) when the source is the system of record and freshness matters; copy to Delta when you need ACID, time travel, or heavy repeated compute on it.
    Expected resultThe 4 partner rows print; bronze.partner_feed exists if you chose to materialize.

    Module 3 · Illustrated Mirror an operational database

    Mirroring continuously replicates an operational database (Azure SQL DB, Cosmos DB, Snowflake, …) into OneLake as Delta — near real-time, no pipelines, and free of compute cost up to a capacity limit. This is how you analyze live operational data without touching the source system.

    Docs: Mirroring overview Mirror Azure SQL DB

    Learn more Mirroring Azure SQL tutorial Cosmos DB
    ▸ Walk through mirroring (or do it live) ~15 min

    What & why: Imagine ContosoMart's inventory lives in an Azure SQL DB. Mirroring keeps an analytics-ready Delta copy in OneLake in sync — so reports use fresh stock levels without hammering the OLTP system.

    Steps (with a live Azure SQL DB):
1. + New item -> Mirrored Azure SQL Database
2. Create a connection to the source (server, database, credentials)
3. Choose Mirror all tables (or just dbo.inventory)
4. Fabric provisions: a landing zone + a replicator + a SQL analytics endpoint
5. Changes publish to OneLake Delta as fast as ~every 15 seconds

    The result looks like lab_data/mirroring-shortcuts/ops-inventory-export.json — an always-fresh inventory Delta table you can query like any other.

    For data prosThree flavors: database mirroring (full CDC replica), metadata mirroring (sync catalog + shortcuts, e.g. Databricks Unity Catalog — no data moved), and open mirroring (your app writes change data to the landing zone via API).

    Note (why illustrated)Mirroring needs a live external database + connection the trial user may not have — so this module is read-along. If you have an Azure SQL DB, follow the tutorial link to do it for real.
    Expected resultYou can describe what mirroring produces in OneLake and how it differs from a pipeline copy.

    Module 4 One copy, every engine

    Because shortcuts and mirrors land as open Delta in OneLake, Spark and T-SQL read the same bytes — and can join to the medallion gold. No export, no second pipeline.

    Docs: Delta tables Mirroring + engines

    Learn more Cross-DB query Shortcuts
    ▸ Join partner + inventory + gold ~12 min

    What & why: Combine the shortcut'd partner feed, the mirrored inventory, and the medallion gold to answer a real question — which products are low on stock and where can we resupply?

    inv  = spark.table("inventory")            # mirrored (or sample import)
gold = spark.table("gold.daily_sales")     # from the medallion lab
(inv.filter("on_hand - reserved < reorder_point")
    .select("sku", "warehouse", "on_hand", "reserved", "reorder_point")
    .show())
    -- Same data via the SQL analytics endpoint
SELECT sku, warehouse, on_hand, reserved, reorder_point
FROM inventory
WHERE (on_hand - reserved) < reorder_point;
    For data prosThis is the payoff: operational data (mirror), partner data (shortcut) and curated analytics (gold) all queryable together, in open Delta, with whichever engine your team prefers.
    Expected resultSKUs below reorder point are listed (e.g. CLD-010 in YYZ-1).

    Module 6 Govern & share across tenants

    Zero-copy extends across organizations: external data sharing lets another tenant consume your live data as a read-only shortcut — governed at the source, no duplication.

    Docs: External data sharing

    Learn more External data sharing Shortcuts
    ▸ Share the partner feed cross-tenant ~10 min

    What & why: ContosoMart could publish the partner feed to a supplier's tenant. External data sharing creates a read-only shortcut in the consumer tenant — both sides see the same live data, governed at the source.

    For data prosMetadata mirroring builds on the same shortcut mechanism, which is why it also supports cross-tenant sharing: live, governed data with no ETL and no copy.
    NoteCross-tenant sharing needs a second tenant + admin enablement, so treat this as read-along in the trial. Governance (roles, sensitivity labels) still applies to shortcut and mirrored data.
