    Secure the agents with Microsoft Defender

    ContosoMart's concierge is live and acting on its own — invoking tools, reading OneLake data, answering anyone. So who's watching the agents? Here you discover every agent, assess its security posture, detect threats in near-real-time, hunt with Advanced Hunting, and govern its identity and data with Microsoft Defender for AI agents — closing the CEO's "see problems before they cost us" mandate over the agents themselves.

    Defender XDR · Security for AI Agent 365 Finale

    Where the story is

    Part 1 built one governed estate; Part 2 put a multi-agent concierge on top (Act 12). Anyone can just ask — and the agents act.

    What still hurts

    Autonomous agents use real tools and data. No inventory, no posture, no threat detection — a prompt injection or a leaked secret would go unseen.

    Module 0 Why secure autonomous agents

    Deployed agents operate autonomously — invoking tools, accessing data and taking actions in response to natural language. That makes continuous discovery, posture and detection essential.

    Learn more: Detect & investigate threats Microsoft Agent 365

    ▸The agent attack surface~5 min

    Intent: name the risk before you manage it.

    • Shadow agents: agents get built across Foundry, Copilot Studio and M365 — nobody has the full list.
    • Prompt injection (XPIA): a poisoned document or web page can hijack an agent that reads untrusted content.
    • Over-privileged tools: an agent with write access to a business system is a high-value target.
    • Secret leakage & evasion: autonomous tool calls can exfiltrate credentials or be steered off-policy.
    For SecOpsTreat an agent like a new class of workload identity: it needs an inventory, a risk score, alerts, and least-privilege access — the same disciplines you apply to users and devices.
    Preview + prereqsMicrosoft Defender security for AI agents builds on Microsoft Agent 365; several capabilities are in preview. Most of this lab is a guided tour — Module 5 (Advanced Hunting) is the hands-on part.

    Module 1 Enable security for AI agents

    Onboarding to Agent 365 turns on discovery, posture and threat detection; the Microsoft 365 connector unlocks investigation and Advanced Hunting.

    Learn more: Enable security for AI agents Agent 365 overview

    ▸Turn on data collection~6 min

    Intent: switch security-for-AI on for the tenant.

    • Sign in to the Microsoft Defender portal.
    • Go to Settings → Security for AI → Get started.
    • Onboarding to Agent 365 enables discovery, posture and threat detection automatically — the Enable toggle is on by default.
    RoleRequires Security Administrator (or higher) in Microsoft Entra ID, plus Agent 365 onboarding.
    ▸Connect the Microsoft 365 connector~8 min

    Intent: collect the observability data that powers alerts and hunting.

    • On the Get started page, select the Microsoft 365 connector step.
    • Select at least Microsoft Entra ID Management events and Microsoft 365 activities (Entra Users and groups is required and pre-selected).
    • Select Connect Microsoft 365; status turns to Connected.
    Expected resultThe setup checklist shows Agent 365 as Done and the Microsoft 365 connector as Connected.
    ▸Onboard Copilot Studio real-time protection~6 min

    Intent: extend real-time blocking to Copilot Studio agents (optional for ContosoMart's Foundry agents, but common in a mixed estate).

    • Select the Copilot Studio step and toggle Real-time protection on.
    • Share the provided URL with a Power Platform administrator and exchange the App ID to complete onboarding.
    NoteFor Copilot Studio agents, if the M365 connector isn't connected, real-time protection still blocks at runtime — but the related alerts and incidents won't appear in the Defender portal.

    Module 2 Discover the agent inventory

    Defender gives one centralized inventory of every agent — Foundry, Copilot Studio, M365 and supported non-Microsoft platforms — with its configuration and security context.

    Learn more: Discover AI agents & posture

    ▸Open the AI agents page~5 min

    Intent: see every ContosoMart agent in one list.

    • In the Defender portal, select Assets → AI agents, then the Agents tab.
    • Use the filter bar to narrow by Agent name, Platform, Publish status, Risk level or Risk indicators.

    The inventory surfaces these risk-related columns:

    Column What it tells you
    Risk level Overall risk computed from the agent's active risk indicators.
    Risk indicators The conditions contributing to that risk level.
    Recommendations Number and severity of active posture recommendations.
    Active alerts Number and severity of active alerts on the agent.
    MCP servers / Tools Connected MCP servers and discovered tools — the agent's reach.
    Expected resultYou can see the ContosoMart Foundry agents you published in Acts 9–12, each with a platform, publish status and risk level.
    ▸Open an agent's page~6 min

    Intent: read the full context Defender holds for one agent.

    • Select an agent to open its details pane, then Open Agent page.
    • The Overview tab can show risk level and indicators, configuration, identity and authentication, attack-surface relationships, active alerts, recommendations, tools and MCP servers.
    • Additional tabs include Security recommendations and Incidents and alerts.
    For SecOpsThis is the same asset-centric investigation model as devices and identities — an agent is now a first-class Defender asset.

    Module 3 Assess posture & risk

    Defender scores each agent from its active risk indicators and, separately, offers security recommendations to improve its posture.

    Learn more: AI agent posture risk Review risk in the portal

    ▸Read the risk level~5 min

    Intent: understand how one score is derived.

    The risk level combines the severity and the combination of active indicators. Inactive or unassessed indicators don't affect it.

    Risk level Meaning
    High Serious combination of active indicators — prioritize for review.
    Medium Notable risk to review and mitigate.
    Low Minor active risk.
    No known risk Assessed, no active indicators.
    Not evaluated Not enough information to assess.
    PreviewAI agent posture risk is in preview; the indicators available depend on the agent platform and the data Defender has.
    ▸Interpret the risk indicators~7 min

    Intent: connect indicators to ContosoMart's agents.

    Indicator What it means · ContosoMart example
    Weak Instructions System prompt lacks guidance for safe, predictable behavior — tighten the concierge's instructions.
    High-usage Agent Used by many people, likely business-critical — the concierge itself.
    Indirect Prompt Injection Exposure May read untrusted content (docs, web) — the Foundry IQ knowledge agent from Act 11.
    Privileged Business-system Access Write access to key systems — watch any agent that can act, not just read.
    Active Threat Active security alerts are associated with the agent.
    For SecOpsAn indicator isn't always "remediate me" — it may reflect intended design (a public chatbot is meant to be unauthenticated). It's context to prioritize, not an automatic failure.
    ▸Act on recommendations~5 min

    Intent: reduce exposure with actionable changes.

    • Open the agent's Security recommendations tab; each is mapped to the risk indicators it helps address.
    • Review Remediation steps and Exposed assets.
    NoteRecommendations are calculated separately from the risk level — a high-risk agent may have none, and a low-risk agent may have one. Review risk level and recommendations together.

    Module 4 Detect & investigate threats

    Defender continuously monitors Agent 365-managed agents and raises near-real-time alerts on suspicious and malicious behavior, correlated into incidents.

    Learn more: Detect & investigate threats

    ▸What Defender detects~6 min

    Intent: know the threat classes before triaging one.

    • Jailbreak attempts and indirect prompt injection (XPIA).
    • Malicious content propagation; secret and credential leakage.
    • Evasion techniques; large language model (LLM) reconnaissance.
    • Suspicious user or IP access to an agent.
    Preview + scopeThreat detection is preview and supported only for published Microsoft Foundry agents — playground-only agents aren't covered. Publish the Act 12 concierge to see detections.
    ▸Investigate incidents & alerts~7 min

    Intent: work an agent threat like any other incident.

    • Alerts from near-real-time detections correlate into incidents; use the incident graph to see involved entities and blast radius.
    • Real-time protection audit and block events are recorded as behaviors in the BehaviorInfo table for correlation.
    • Optionally enable prompt evidence to include the triggering prompt snippet in alerts (on by default).
    Expected resultAn agent alert opens into an incident with the agent, user and tool entities linked — triage, correlate and hunt from there.

    Module 5 Hunt with Advanced Hunting hands-on

    The AgentsInfo table is your agent inventory as queryable data. This is the runnable module — paste each query into Advanced hunting and run it against your tenant.

    Learn more: AgentsInfo table Advanced hunting

    ▸List the agent inventory~8 min

    Intent: get the latest state of every agent. The table stores multiple snapshots per agent, so use arg_max(Timestamp, *).

    • Go to Investigation & response → Hunting → Advanced hunting.
    • Paste and run:
    AgentsInfo
| summarize arg_max(Timestamp, *) by AgentId
| where LifecycleStatus != "Deleted"
| project AgentName, Platform, PublishedStatus, LifecycleStatus, Owners, Model, CreatedDateTime
| sort by CreatedDateTime desc
    Expected resultOne row per live agent, newest first. To use Microsoft's prebuilt hunts, open the Queries tab and select AI Agents.
    Table renameThe AIAgentsInfo table is being replaced by AgentsInfo. Use AgentsInfo; the old name is accessible only until 2026-07-01.
    ▸Surface risky configuration~8 min

    Intent: find the published, broadly-available agents that expose external MCP servers or tools — the ones to review first.

    AgentsInfo
| summarize arg_max(Timestamp, *) by AgentId
| where LifecycleStatus != "Deleted"
| where PublishedStatus == "Published"
| where isnotempty(McpServers) or isnotempty(DeclaredTools)
| project AgentName, Platform, Availability, McpServers, DeclaredTools, DeclaredDataSources
    For SecOpsMcpServers, DeclaredTools and DeclaredDataSources describe the agent's reach — the practical blast radius if it's compromised.
    ▸Correlate agents with alerts~9 min

    Intent: join the inventory to alert evidence to see which agents currently have alerts. (Needs the M365 connector from Module 1.)

    let agents = AgentsInfo
    | summarize arg_max(Timestamp, *) by AgentId
    | where LifecycleStatus != "Deleted";
AlertEvidence
| where Timestamp > ago(7d)
| join kind=inner agents on $left.AgentId == $right.AgentId
| project Timestamp, AgentName, AlertId, Platform, EntraAgentId
    Expected resultAgents with alerts in the last 7 days, ready to pivot into the incident. The full query set is in lab_data/defender-ai-agents/agent-hunting-queries.kql (identity, orchestration and activity hunts too).

    Module 6 Govern identity & data — and close the saga

    Defender detects; Entra and Purview prevent. Defense in depth means governing the agent's identity and the data it can touch — the same disciplines you built in Part 1.

    Learn more: Secure Gen AI with Entra Purview for AI agents Purview for AI apps

    ▸Govern agent identity (Entra Agent ID)~6 min

    Intent: give every agent a governed identity and least privilege.

    • Each agent carries an Entra Agent ID — the EntraAgentId and EntraBlueprintId columns in AgentsInfo tie the agent to its enterprise identity and its identity blueprint (template).
    • Apply least-privilege, Conditional Access and PIM to the identities and workload identities behind agents; monitor for over-privilege and unusual activity.
    Callback to Act 10The Fabric tool used identity passthrough (On-Behalf-Of) so the agent could only ever see what the user could. Governed identity is what makes that guarantee hold.
    ▸Govern agent data (Purview)~6 min

    Intent: keep the data the agents touch classified, protected and audited.

    • DSPM for AI discovers and reports AI/agent usage across the org.
    • Sensitivity labels + DLP ensure agents never return data a user can't access; audit captures prompts and responses.
    • Insider Risk Management — the Risky AI usage template — flags prompt-injection and protected-material access, feeding signals into Defender XDR.
    Callback to Act 7These are the same Purview sensitivity labels and policies you applied to the ContosoMart estate in Part 1 — now extended to agent interactions.
