    Your first Foundry agent

    You have a governed Fabric data agent (Act 8). Now build the assistant that will reason and act on top of it. In this lab you create an Azure AI Foundry project, deploy a model, and build + test a prompt agent in the portal — the managed runtime you'll ground in ContosoMart's Fabric data next.

    Foundry Agent Service Prompt agent Portal + SDK

    Where the story is

    Act 8 shipped ContosoMart Analyst — a governed, read-only Q&A agent over OneLake. It answers data questions, but it can't plan, call tools, or publish to Teams.

    What still hurts

    ContosoMart wants an assistant that reasons over a request, uses tools, and lives where people already work. That's Foundry Agent Service.

    Module 0 What Microsoft Foundry is

    Foundry unifies agents, models and tools under one Azure resource with built-in RBAC, networking, policies, tracing and evaluations — so you build once and govern centrally.

    Docs: What is Foundry Agent Service

    ▸Prompt vs hosted vs Responses API~6 min

    Intent: pick the right build approach before you start. Foundry is a spectrum from declarative to full code.

    • Prompt agent — declarative: instructions + model + tools; Foundry hosts and runs it, no code or containers. Start here.
    • Hosted agent — your own code/framework (Agent Framework, LangGraph, OpenAI/Anthropic SDKs) packaged as a container; Foundry runs it with a managed endpoint, scaling and identity.
    • Responses API — an ephemeral agent defined entirely in your app code, no persisted Foundry resource.
    For buildersYou can start declarative and move to code as needs grow — the model and tools carry over.
    Expected resultYou can justify choosing a prompt agent for ContosoMart's first assistant.

    Module 1 Create a project & get access

    A Foundry project is where your agents, models and connections live. You need an Azure subscription and the right RBAC role.

    Docs: Get started RBAC in Foundry

    ▸Create a Foundry resource + project~8 min

    Intent: get a project endpoint to build against.

    • Open the Foundry portal and make sure the New Foundry toggle is on.
    • Create a Foundry resource (single Azure resource with projects) and a project named contosomart.
    • Note the project endpoint — https://<resource>.ai.azure.com/api/projects/contosomart.
    NoteComing from Azure OpenAI? You can upgrade an existing resource to a Foundry resource and keep your endpoint and keys.
    ▸Assign the Foundry User role~5 min

    Intent: make sure you (and later, end users) can build and run agents.

    Assign at least the Foundry User Azure RBAC role on the project. (This role was previously named Azure AI User; the IDs and permissions are unchanged.)

    Expected resultYou can open Build → Agents in the portal for the contosomart project.

    Module 2 Deploy a model

    An agent is a model paired with instructions and tools. Pick an orchestration model from the catalog and deploy it.

    Docs: Foundry Models

    ▸Choose & deploy an orchestration model~8 min

    Intent: give the agent a brain that supports agent tool-calling.

    • In Build → Models, browse the catalog (10,000+ models). Filter for agent-capable models (e.g. a GPT-4.1 / GPT-5-mini class model).
    • Deploy it and note the deployment name (e.g. gpt-4.1-mini).
    For buildersModels are swappable — you can change the agent's model later without rewriting the agent.
    Act 10 noteThis model only orchestrates and writes the response; it does not change which model the Fabric data agent uses for NL2SQL.

    Module 3 Build the ContosoMart prompt agent

    Define instructions, choose the model, and attach a built-in tool — all declaratively in the portal. No application code yet.

    Docs: Create a prompt agent Toolbox & tools

    ▸Create the agent with instructions~8 min

    Intent: shape the assistant's persona and boundaries.

    In Build → Agents → Create, name it contosomart-concierge, select your model, and set instructions:

    You are the ContosoMart concierge, an assistant for the coffee retailer's staff.
Be concise and cite where a fact came from. If a question needs live business data
(sales, inventory, customers), say you will look it up. Never invent numbers.
    ForeshadowingRight now the agent has no data tool, so it can't answer "what did we sell last week?" — that's exactly what Act 10 fixes.
    ▸Add a built-in tool~6 min

    Intent: see how tools extend an agent, using a simple one first.

    Attach a built-in tool such as Web search or Code interpreter from the toolbox. Tools are grouped in a Toolbox — one managed MCP-compatible endpoint any agent can consume.

    For buildersA toolbox centralizes auth, governance and versioning, so you update a tool once instead of rewiring every agent.

    Module 5 From portal to code (and publishing)

    The same prompt agent can be defined in code for CI/CD, and published to a stable endpoint for Teams and Microsoft 365 Copilot.

    Docs: Prompt agent (code) Publishing & sharing

    ▸Define the agent in code~10 min

    Intent: version the agent with your app and prepare for Act 10's Fabric tool.

    from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import PromptAgentDefinition

PROJECT_ENDPOINT = "https://<resource>.ai.azure.com/api/projects/contosomart"

project = AIProjectClient(endpoint=PROJECT_ENDPOINT, credential=DefaultAzureCredential())
openai = project.get_openai_client()

agent = project.agents.create_version(
    agent_name="contosomart-concierge",
    definition=PromptAgentDefinition(
        model="gpt-4.1-mini",
        instructions="You are the ContosoMart concierge. Never invent numbers.",
    ),
)
print(f"Agent: {agent.name} v{agent.version}")

resp = openai.responses.create(
    input="Introduce yourself in one sentence.",
    extra_body={"agent_reference": {"name": agent.name, "type": "agent_reference"}},
)
print(resp.output_text)
    var projectEndpoint = "https://<resource>.ai.azure.com/api/projects/contosomart";
AIProjectClient projectClient = new(new Uri(projectEndpoint), new DefaultAzureCredential());

DeclarativeAgentDefinition def = new(model: "gpt-4.1-mini")
{
    Instructions = "You are the ContosoMart concierge. Never invent numbers."
};
AgentVersion agent = projectClient.AgentAdministrationClient
    .CreateAgentVersion(agentName: "contosomart-concierge", options: new(def));
Console.WriteLine($"Agent: {agent.Name} v{agent.Version}");
    AuthSign in with az login; DefaultAzureCredential uses your identity. Keep tokens out of source control.
    ▸Publish to a stable endpoint~5 min

    Intent: know how the agent reaches real users.
