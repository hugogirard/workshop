    One concierge now juggles numbers and knowledge — and it's getting muddled.     Workflows · A2A Router + specialists Capstone

    Where the story is

    The concierge grounds numbers in Fabric (Act 10) and documents in Foundry IQ (Act 11). It works — but one agent owns everything.

    What still hurts

    An overloaded single agent is hard to trust, debug and extend. Adding a "forecast" or "translation" skill means rewriting one big prompt.

    Module 0 Why split into multiple agents

    Traditional single-agent systems struggle with complex, multifaceted tasks. Orchestrating focused agents makes the system more robust, adaptive and maintainable.

    Docs: Workflows Agent Service

    ▸Specialize, then route~5 min

    Intent: understand the payoff before you build.

    • Each agent owns a narrow job → easier to test, trace and trust.
    • A router/orchestrator delegates by intent — no hand-coded if/else in a mega-prompt.
    • Add a new capability (e.g. demand forecast) by adding an agent, not rewriting one.
    For buildersThis mirrors good service design: small, focused, composable units behind one entry point.

    Module 2 Build the workflow

    Workflows orchestrate agents visually — pick a pattern and drop in agent nodes.

    Docs: Create a workflow

    ▸Choose a pattern~5 min

    Intent: match the pattern to the concierge.

    Pattern Use it for
    Group chat Dynamically pass control between agents by context — best for our router → specialist routing.
    Sequential Pass one agent's result to the next in order — e.g. fetch numbers, then have knowledge agent add policy context.
    Human in the loop Pause for approval — e.g. before a reorder recommendation.
    ▸Create it in the portal~12 min

    Intent: build and wire the nodes.

    • In the Foundry portal (New Foundry on), select Build → Create new workflow and pick Group chat.
    • Add Agent nodes and assign your numbers agent and knowledge agent (create them from the Act 10/11 configs if needed).
    • Add Logic nodes for any routing rules; use Data transformation to capture structured output.
    • Select Save after every change — workflows don't autosave.
    NoteHosted agents aren't supported in the workflow designer — assign prompt agents here; orchestrate from hosted-agent code with Agent Framework (Module 4).

    Module 3 Route & test the team

    Docs: Run & verify

    Intent: see the agents collaborate.

    Module 4 Code-first: A2A & Agent Framework

    Foundry is moving workflow authoring to code-first. Learn the durable ways to make agents talk to each other.

    Docs: A2A endpoint Agent Framework workflows

    ▸Know the retirement & migration paths~6 min

    Intent: build something that lasts past the portal designer.

    RetirementFoundry retires in-portal workflow execution and the visual designer on Dec 1, 2026. YAML workflow definitions still run when deployed as a hosted agent. (Connected agents "classic" is also deprecated, retiring Mar 31, 2027.)

    If you want to… Use
    Keep orchestration on a code-first runtime Microsoft Agent Framework (recommended; reuse exported workflow YAML)
    Keep a fully visual low-code designer Azure Logic Apps (calls Foundry agents as steps)
    Let one agent call another, no formal workflow A2A — expose an agent as an agent-to-agent endpoint
    TipExport your workflow's YAML from the designer before it retires — it's the portable artifact you carry into Agent Framework.
